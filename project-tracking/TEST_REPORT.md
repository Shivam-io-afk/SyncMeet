- No real Gemini success, Google OAuth exchange, email/OTP delivery, screen share, browser speech recognition, or cross-network WebRTC has been measured.

## Backend route audit continuation — 2026-10-09

- Replaced remaining Mongoose `new: true` update options in meeting-feature and history routes with `returnDocument: 'after'`; `rg` found no remaining `new: true` uses under `server`.
- Reviewed authenticated room creation and found that reusing a same-owner ended room ID reactivated stale meeting state. The endpoint is now create-only, supplied IDs are validated, generated IDs use UUIDs, and duplicate-key conflicts return 409.
- The UI-authenticated room reuse and new-ticket cases run in the in-memory integration path. Atlas duplicate-write races and unrelated feature-route persistence are not represented by these tests.

- The active browser pages were not shared during this pass. The UI's actual microphone mute → page refresh → restored track state was therefore not tested; the socket integration test covers server state and the client setter is build-checked.
